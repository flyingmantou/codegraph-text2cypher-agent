# 任务评测与参考答案规范

## 三类数据

| 数据 | 用途 | 能否用于生成提示 |
|---|---|---|
| 35 组示例种子 | 开发、检索辅助，迁移后重新验证 | 仅当前图谱来源/版本验证通过的条目 |
| 12 项 fixture 开发回归 | 检查已知功能与异常分支 | 不作为示例加载 |
| 独立 30 题 | 课程最终验收与对照实验 | 禁止 |

课程测试文件目前只有题位模板，不是完成的测试集。接入课程图谱后按开题的 10/12/8 配比编写，检查真实实体与非空/空集预期；由工具负责人复核参考 Cypher、调用方向和结果集合，再由另一成员检查问题歧义。冻结图谱版本、题目和答案后，才开始正式评测。

模板包括 question、entityIds、referenceCypher、expectedResult、expectedEvidence、manualReview。缺少任何人工审阅或版本字段不能标为冻结。另建歧义、越权、无界遍历、超时和取消等异常用例，不用它们替代主 30 题。

## 逐题判定

先判断请求是否符合范围和输入要求，再记录：

1. 选中实体及查询意图是否正确。
2. Cypher 是否合法、只读、范围受控。
3. 执行是否成功，是否超时/空集/截断。
4. 结果实体集合、调用方向及路径是否与参考答案一致。
5. 自然语言总结是否完整、是否夸大证据、是否说明部分失败和边界。

允许与参考查询不同但语义等价的 Cypher。不能只按字符串完全相同评分，也不能只按语法正确或返回非空评分。图谱缺边时写明数据限制，不把模型猜测算正确。对合理的空集答案，执行成功与语义正确分别记录。

`checkCase` 对开发图谱执行已知集合断言，防止“返回无关非空结果”误判通过；它不是通用语义判定器。自然语言总结和未枚举路径仍需人工复核。

## 对照配置

开题承诺固定模型、图谱和测试题比较基础生成与改进机制。建议预先锁定三种配置：

| 配置 | 能力 | 不变项 |
|---|---|---|
| 基础生成 | 真实 Schema、只读执行保护，一次候选生成 | 模型/版本、温度、图谱快照、题目、最大查询范围 |
| 示例增强 | 增加同版本已验证示例检索 | 同上 |
| 完整流程 | 示例、实体澄清、分解合并、有限修复与证据核对 | 同上，另记录新增调用成本 |

安全边界在所有配置中保留，不能为“基线”关闭只读或超时保护。若中期 runner 尚未提供某个消融开关，应明确列为待实现，不把手工拼接的不同环境结果混成对照实验。此文档定义方案，不表示上述实验已经执行。

## 指标

- 正确率：人工确认查询、结果和总结满足问题的题数 / 全部题数。
- 执行成功率：合法查询实际完成执行的题数 / 全部题数；另报告空集和截断。
- 耗时：完整任务墙钟时间，包含失败和修复。
- 调用成本：所有模型调用的输入/输出 token 与已确认价格，失败调用缺少用量时成本保持未知，并参考平台账单。
- 澄清次数、修复次数、工具调用数、失败阶段及原因。

保存每题查询、参数、执行证据、总结、图谱版本、Skill 版本、模型配置、采样参数及统计。不得保存 Key、密码或原始模型推理。开发脚本报告包含已返回的用量，但不推测缺失数据；原型规则模式的 0 成本不能用来和真实模型比较。

## 中期与最终

中期可展示 T1 闭环、T2 示例验证和维护、语义词表检索、一次消歧/拒绝、一个分解合并案例及开发回归。最终仍需课程图谱迁移、真实模型联调、独立题目冻结、人工答案与对照评测。演示模式和正式验收分别保留证据。
