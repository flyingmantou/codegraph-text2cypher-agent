# 命名与开发约定

- 四模块源码、测试、说明均随各自目录，公共类型只放contracts；不要把业务实现复制到多个包。
- TypeScript ESM，显式`.ts`导入，Node 24原生可擦除类型；普通函数camelCase，类型PascalCase，常量UPPER_SNAKE_CASE。工具名snake_case；状态与分类沿公共契约。
- 一个语义稳定的入口对应一项工具；参数、结果、错误码都必须可序列化。MCP与dsh适配复用同一个工具实现。
- GraphNode.id是身份依据，名称仅用于检索；合并不按显示名称去重。禁止把同名方法合并成一个节点。
- 所有查询参数化；工具内部验证，runtime不能用模型承诺代替执行门控。
- signal贯穿模型、工具、数据源和队列；收到取消后不进行后续修复或排队写入。原子rename是示例持久化提交点。
- 示例修改撤销验证；生成提示只用当前图谱同版本已验证示例。评测模板与开发回归不能混入示例库。
- 日志和用户错误使用稳定代码，不输出供应商原始错误体、密钥或连接密码；模型输出不是可信HTML。
- 默认源码不带运行凭据。报告必须标明fixture/demo/standalone/dsh等实际来源；未实测项保留待验。
- 每人维护自身模块测试与说明。公共接口有变化时先更新契约，协调调用方，再跑跨模块回归。
