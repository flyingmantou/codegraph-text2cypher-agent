# Web 查询工作台

负责人：王雯迪。此模块负责浏览器交互、结果展示与界面侧输入检查。静态资源在 `public/`，由 Harness HTTP 服务提供；浏览器不直接连接模型或 Neo4j。

## 运行与依赖

将四个模块合并到同一项目后，从项目根目录按根 README 启动服务，打开 `http://127.0.0.1:3000`。不要直接双击 HTML 文件：模块加载和 `/api/` 请求依赖同源 HTTP 服务。

本模块无需构建和 npm 依赖。使用 Node.js 24.22.3 或更高版本，模块测试可独立运行：

```sh
node --test apps/web/tests/*.test.js
# 也可进入 apps/web 后执行 npm test
```

模块只依赖公共 HTTP 契约，不导入 Harness、Skill 或工具的内部代码。

## 页面与交互

- 查询工作台：简单／中等／复杂三档入口、自然语言输入、同名实体选择、取消请求。
- 查询结果：状态和限制说明、计划分支、数据表、Cypher 与参数、执行证据 ID、模型／工具调用和 token 统计。
- 关系子图：节点属性、关系方向、SVG 缩放、关系明细。按实体 ID 区分同名节点。
- 批量查询：粘贴多行问题，或上传 TXT／JSON 字符串数组，每批最多 10 题。批次继承提交时选定的复杂度，点击逐题结果可查看完整记录。
- 示例知识库：新增、编辑、删除、分类筛选、关键词／领域语义／混合检索、执行验证状态与图谱版本。
- 运行说明：显示服务端真实的图谱、模型、运行器、Skill 版本、工具清单和资源限制。
- 报告导出：下载当前运行对应的 Markdown，内容由后端生成。

界面显示的是查询完成后返回的实际执行记录，不以预设动画冒充实时工具事件。复杂度随请求传给后端，实际分解以返回的查询计划为准。没有收到 `runtime` 或来源信息时显示“未标注／未知”，不默认声称运行于 dsh 或真实图谱。

## HTTP 契约

| 请求 | 用途 |
|---|---|
| `GET /api/health` | 来源、运行器、Skill、工具及预算 |
| `GET /api/schema` | 图谱标签、属性、关系方向与版本 |
| `POST /api/query` | `{question, complexity, entityId?}` |
| `POST /api/batch` | `{questions: string[], complexity}`，最多 10 题 |
| `GET /api/examples?q=&category=&mode=` | 示例检索，mode 为 lexical／semantic／hybrid |
| `POST /api/examples` | 保存完整示例，编辑后由工具层撤销旧验证状态 |
| `DELETE /api/examples/:id` | 删除指定示例 |
| `POST /api/examples/verify` | 显式运行示例验证 |
| `GET /api/runs/:id/report` | 下载 Markdown 报告 |

QueryResponse 以根目录 `contracts/index.ts` 为准。前端消费 `plan`、`evidenceIds`、`source.runtime`、`source.skillVersion` 等字段；未提供计划和证据时不编造展示。

## 数据与凭据边界

用户文本、模型结果、节点属性、报告内容均作为文本处理，不写入 `innerHTML`。动态内容使用 `textContent`；图形只设置 SVG 属性，缩放通过 `viewBox` 实现，兼容服务端禁止内联脚本与样式的 CSP。页面不读取 API Key 或数据库密码，不使用本地存储持久化这些信息。

输入限制是交互保障，后端仍须独立校验。点击取消会中止 fetch，服务端通过断连取消信号停止当前任务；不能仅凭前端按钮断言数据库已经立即停止。

## 已验证与待验收

已运行 9 项 Node 测试，覆盖查询／澄清请求、复杂度与批量顺序、输入拒绝、检索编码、错误／取消、报告路径、文件解析、来源标记和同名节点布局。静态检查确认 DOM ID 唯一、代码中的固定 ID 均存在、没有内联事件／样式或 `innerHTML`。

这些属于浏览器模块的纯函数与传输契约测试，没有代替浏览器端到端操作。当前执行环境曾禁止监听本地端口，真实浏览器与服务的联合验收须在可正常启动服务的电脑补做。可按下面演示步骤记录实际结果。

## 中期演示步骤

1. 打开运行说明，核对来源、Skill 版本和工具清单；人工样例／规则模式必须保留标记。
2. 在示例库运行“验证全部示例”，核对来源、版本、成功数与失败数。
3. 简单查询 `查询 getAllFood 方法`，展示参数化 Cypher、结果与执行证据。
4. 查询 `查询 getOrder 方法`，选择不同候选实体，对照不同 ID 的结果。
5. 复杂查询 `placeOrder 的 RPC 和 MQ 综合依赖是什么？`，核对计划分支、合并后的结果与关系明细。
6. 新建或编辑示例，确认验证状态重置；用语义与关键词检索分别查看匹配结果。
7. 上传包含正常查询、歧义问题和危险请求的三题文件，逐题检查状态。
8. 下载 Markdown；对照界面和报告中的运行 ID、查询及证据。

任务评测集和效果统计由 Skill 模块负责，前端仅展示后端返回的真实结果。
